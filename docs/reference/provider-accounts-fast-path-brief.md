# Bluey — Provider Accounts & Fast Path: implementation brief for a coding agent

Reality-grounded agent brief for two Bluey features: (1) a **Provider Accounts** layer that lets the owner sign in with the paid AI subscriptions they already have — ChatGPT Free/Plus/Pro via Codex OAuth, Claude Pro/Max via claude.ai OAuth in the Claude Code wire format, Google AI Pro/Ultra via Antigravity OAuth — with per-account model discovery, one versioned request fingerprint per provider, runtime drift detection and an extra-usage guard; (2) a **fast-path** latency overhaul with a measurable budget: small readable screenshots, OCR off the critical path, parallel retrieval, warm connections, prefix-stable prompts.

This brief itself is committed as `docs/reference/provider-accounts-fast-path-brief.md`. The decisions it records are ADR 0009 (provider accounts) and ADR 0010 (fast-path latency budget); the dated wire facts live in `docs/PROVIDER_ACCOUNTS.md` and `docs/LATENCY.md` — those two documents, not this brief, are the ones to update when a provider changes something.

**Errata from the 2026-09-11 verification pass** (sources and detail in `docs/PROVIDER_ACCOUNTS.md`, `docs/LATENCY.md` and `docs/reference/verification-2026-09-11/`; where this brief and those documents disagree, the documents win):

- *Codex* — the CLI requests six scopes (adds `api.connectors.read api.connectors.invoke`); it sends **no** `OpenAI-Beta: responses=experimental` header on HTTP; the code exchange is form-encoded but refresh is JSON; port 1455 has a registered fallback 1457; the device flow runs through `…/api/accounts/deviceauth/{usercode,token}` and returns an authorization code (`/codex/device` is only the user page); session headers are `session-id` / `thread-id` / `x-client-request-id`; rate limits come as `resets_at` and `x-codex-*-reset-at`; the CLI sends the catalog's `instructions_template` as `instructions` (replay test in PR 3a).
- *Claude* — the token endpoint is `https://platform.claude.com/v1/oauth/token` (the `console.anthropic.com` one is Cloudflare-blocked for non-browser POSTs); the `cli` entrypoint's identity text is still *"You are Claude Code, Anthropic's official CLI for Claude."* — the Agent-SDK text belongs to the sdk/vscode entrypoints; the billing block is `system[0]` and the identity `system[1]`, and Bluey's own prompt must **not** be a further `system` block (it becomes a mid-conversation system message); Bearer is the only transport; the always-on beta list is longer; Claude Code's loopback port is 54545.
- *Antigravity* — Google's Antigravity terms now name third-party software using Antigravity OAuth a breach with account suspension as the consequence; five scopes; fixed redirect port 51121; the header set in §1 and §4c is the archived plugin's pre-2026-02 behaviour (the maintained reference sends only `User-Agent`, `Authorization`, `Content-Type` over HTTP/1.1 without ALPN); there is no cross-host cascade any more; `v1internal:fetchAvailableModels` exists; the model list in §1 and §4c.4 is stale.
- *Fast path* — Gemini's unspecified media resolution bills like HIGH (1,120 tokens per image), so the hint must always be explicit; implicit caching on Gemini 3.x Flash starts at 4,096 tokens, not ~1 K; `gemini-3.8-flash` rejects `thinkingLevel: minimal` (Flash-Lite accepts it); OpenAI's `detail: auto` is full resolution on current models.

## 2. Product decision — all three subscriptions are built

Owner decision (2026-09-11): **all three subscription sign-ins are built.** Bluey is a personal tool used by its owner with their own accounts; the integrations follow the same pattern as CLIProxyAPI, vibeproxy, T3 Code and the opencode auth plugins. The only things the ToS situation changes are *engineering* requirements: fingerprint parity, drift detection, an extra-usage guard, and automatic fallback.

| Credential source | Build | Engineering notes |
|---|---|---|
| **API keys** (Gemini, Azure Foundry, Anthropic, OpenAI-compatible) | Primary path, unchanged. | Always the fallback target when a subscription account is `NeedsReauth` / `Unavailable` / rate-limited. |
| **ChatGPT Free / Plus / Pro — Codex OAuth** | Yes (PR 3a). | Fixed loopback port 1455 → device-code fallback; Responses dialect to the Codex backend; catalog from `/backend-api/codex/models`; plan from the ID token. Fingerprint: `originator` + headers + `client_version`. |
| **Claude Pro / Max — claude.ai OAuth, Claude Code wire format** | Yes (PR 3b). | Reuse the existing Anthropic Messages codec; add a `ClaudeCodeFingerprint` request shaper (identity + billing-header system blocks, `metadata.user_id`, session header, UA/betas) pinned to a Claude Code version and validated against a real capture; **extra-usage guard**: the moment a response says requests are drawing from extra usage, stop, mark the account `Unavailable{fingerprint_drift}`, fall back, and tell the user — never silently spend paid credits. Optional second Anthropic option: **Console sign-in → mint an API key** (`org:create_api_key`), which is plan-independent pay-as-you-go. |
| **Google AI Pro / Ultra — Antigravity OAuth** | Yes (PR 3c). | Google PKCE with the Antigravity client; `loadCodeAssist` for project + tier; `v1internal:streamGenerateContent` with the Code Assist wrapper and endpoint cascade; per-account device fingerprint; model list discovered, not hard-coded; optional multiple Google accounts with rotation on 429 (the owner's own accounts). |

**Design consequences**

- The durable asset is the **Accounts abstraction** (§3): credential sources are pluggable (`ApiKey`, `OAuthSubscription`), and each provider contributes an OAuth profile, a *request shaper* (its fingerprint), a catalog fetcher and an error mapper — nothing else in the app knows which provider is "official".
- **One consent dialog per provider, once**, stating plainly: unofficial integration, uses your own plan limits, the provider may change or block it, Bluey will stop and tell you rather than bill extra usage. After that, no nagging.
- **Fingerprints are data with a date.** Each lives in one module (`bluey-protocols::fingerprints::{codex, claude_code, antigravity}`) with `VERSION`, `CAPTURED_ON`, a scrubbed golden capture in `tests/fixtures/fingerprints/`, and a dev command to re-diff against a fresh capture. Drift is detected at runtime (specific error strings / status codes) and surfaced as `account.fingerprint_drift`.
- **Fallback order** is explicit and user-visible: subscription account → API-key provider for the same role → router's existing fallback chain. A subscription account that is rate-limited for its window is skipped for that window (reset time shown), not retried in a loop.
- The research sidecar (`bluey-agent`) keeps using **API keys**: the Codex backend is stateless and tool-hostile for that loop, the Claude fingerprint would have to be re-implemented in TypeScript, and the Antigravity wrapper has no function-calling parity — not worth it for a background job.
- Optional convenience (owner's own machine): **Import existing sign-ins** from Claude Code, Codex CLI and Antigravity local credential stores (§3.8) as an alternative to a fresh browser flow.

## 3. Provider Accounts layer — target design

## 5. Fast Path — latency budget, image pipeline, OCR policy

**5.1 Reframe the target.** "120–500 ms" cannot be an end-to-end target for a cloud LLM: the model's own time-to-first-token (TTFT) on the fastest Flash models is typically 300–800 ms from a warm connection and is outside our control. It **is** the right budget for everything Bluey does *before* the network. Targets to prove with the bench in §7, measured from the ⌘↵ keydown on a warm connection, `gemini-3.5-flash-lite`, one 1440-px screenshot, ≤ 2.5 K prompt tokens:

| Stage | Target p50 | Target p95 | Notes |
|---|---|---|---|
| Shortcut → capture finished (SCK + downscale + JPEG) | ≤ 90 ms | ≤ 150 ms | window capture, 1440 px, q 0.65 |
| AX snapshot (soft deadline, raced) | ≤ 80 ms or dropped | — | include if ready, else omit from *this* request |
| OCR on the critical path | **0** | 0 | runs async, see 5.4 |
| Retrieval (parallel with capture) | ≤ 15 ms keyword; embedding only from cache | — | 5.5 |
| Fuse + budget + prompt build (TS) | ≤ 15 ms | ≤ 30 ms | |
| IPC + base64 + serialization | ≤ 20 ms | ≤ 40 ms | image ≤ 250 KB |
| **Local total before the request leaves** | **≤ 150 ms** | **≤ 300 ms** | the "120–500 ms" budget, kept honest |
| Connect (pre-warmed) + upload | ≤ 60 ms | ≤ 120 ms | 5.6 |
| Provider TTFT (flash-lite, minimal thinking) | 300–700 ms | ≤ 1200 ms | measure, don't promise |
| First token → first paint | ≤ 16 ms | — | render on first chunk |
| **⌘↵ → first visible token** | **≤ 800 ms** | **≤ 1500 ms** | headline number for the PR table |

Perceived speed also comes from *starting earlier* (5.8) and *showing progress instantly* (state pill → "Capturing…" within one frame).

**5.2 Instrumentation first (PR 4a).** Add `LatencyTrace { request_id, trigger, t_shortcut, t_capture_done, t_snapshot_ready, t_retrieval_done, t_prompt_built, t_request_sent, t_response_headers, t_first_token, t_first_paint, t_done, image_bytes, image_px, prompt_tokens, provider_id, model }`. Rust owns the timestamps it can see (shortcut, capture, headers, first token) and TS the rest (snapshot ready, prompt built, first paint); merge by `request_id` and persist in the `ai_requests` metrics record; emit `ai.trace` (dev-only) so the dev overlay shows p50/p95 over the last 50 requests per stage. Add `dev_bench_fast_path { iterations, provider }` (dev-tools feature) and `bun run bench:fastpath` that runs it against the mock provider (local stages only, deterministic) and, when a key is present, against the real provider, printing a percentile table. Every fast-path PR pastes before/after tables in its description.

**5.3 Image pipeline — "readable, not big".**

- Capture the **active window** when one is focused (already supported by the helper), the display otherwise; the HUD stays excluded.
- Downscale to a **long edge of 1440 px** (from 1600) — at 1× logical resolution UI text remains legible to both humans and models; expose `Screen detail: Auto / Standard / High` in Settings (High = 1600–1800 px + provider high-resolution hint for tiny text).
- **JPEG quality 0.65** (from 0.8), 4:2:0 chroma, alpha stripped, no metadata; target **≤ 250 KB** per frame. Add a legibility guard test in `scripts/test-helper.sh`/Swift tests: Vision OCR over the fixture screens must agree ≥ 98 % (token-level) between q 0.8 and q 0.65 encodings, otherwise raise quality. Try WebP (Gemini/OpenAI accept `image/webp`) only if `CGImageDestination` on macOS 14 can encode it (**VERIFY**; if not, stay JPEG).
- **Provider resolution hints:** Gemini per-part `mediaResolution` — `MEDIUM` by default, `HIGH` when the frontmost bundle id is in a dense-text allow-list (Xcode, VS Code, Cursor, JetBrains, Terminal, iTerm, Warp, Ghostty, Zed, Excel/Numbers, browsers on code hosts) or the user sets High (**VERIFY** enum names and token costs for 3.8-flash in `docs/reference/gemini-api-sept-2026.md`). OpenAI Responses `input_image.detail`: `low` for chat screens, `high` for dense text. Anthropic: no hint; keep ≤ 1568 px long edge. This alone roughly halves image prefill tokens on chat-style screens.
- Never route inline images through the Files API on the fast path; keep dHash de-duplication so an unchanged screen reuses the previous frame id.

**5.4 OCR policy — keep it, take it off the critical path.** Vision models read screenshots well enough that OCR should not gate the first request, but OCR is still the cheapest way to (a) serve text-only models and follow-up turns without re-sending an image, (b) make the session searchable (FTS), (c) feed the proactive classifier and privacy scrub, and (d) keep code fidelity when a user asks about small text. Therefore:

- `buildNativeSnapshot` returns as soon as the frame is encoded; **OCR and AX are not awaited**. AX runs with an **80 ms soft deadline** (its `focusedElement.value`/`selectedText` are high-value and usually fast) — include if ready, else omit. Refactor `context/mod.rs:77-78` from one `join!` into: `join!(frontmost, capture)` → return; spawn OCR (+ late AX) as an enrichment task that publishes `context.enriched { snapshot_id, ocr, accessibility }`.
- TS consumes `context.enriched` to attach OCR text to the saved response/session event, to the FTS index, and to the *next* turn's context (follow-ups reuse OCR text instead of the image when the screen hash is unchanged).
- Default OCR level for the enrichment path: `fast` (matches the docs; `accurate` only when Screen detail = High).
- A new setting `Screen input: Image (default) / Image + text / Text only` covers non-vision models and users who prefer text; `Text only` awaits OCR (with its 5 s timeout) — that is the one path where OCR stays on the critical path, by choice.
- Regression test: an integration test asserting `buildNativeSnapshot` resolves without OCR and that `context.enriched` arrives later.

**5.5 Retrieval in parallel, embedding off the hot path.** In `engine.ts` start `retrieveRelevantContext` **concurrently** with `buildNativeSnapshot` (`Promise.all`) — it depends only on instruction + transcript + mode. Add `RetrievalStrategy::Fast` (`documents_retrieve`): FTS5 keyword only, plus semantic **only if** a query embedding is already cached (Rust LRU keyed by sha256 of the normalized query, 256 entries, 30 min TTL). Populate the cache proactively: while listening, embed the last detected question (debounced 2 s, only when `embeddings_ready()` and a document library exists) so ⌘⇧↵ / ⌘↵ are cache hits; `Balanced`/`Deep` requests keep full hybrid retrieval. Test: fast path issues zero embedding calls when the cache is cold.

**5.6 Connection warm-up.** Configure the shared `reqwest::Client` with `pool_idle_timeout(90s)`, `tcp_keepalive(30s)`, `http2_keep_alive_interval(30s)`, `http2_keep_alive_while_idle(true)`. Add `AiManager::warm(provider_id)` that issues the cheapest authenticated request (Gemini `GET /models/{fast_model}`; Codex `GET /backend-api/codex/models`) at boot, when the HUD becomes visible, when listening starts, and every 45 s while the HUD is visible or listening — never more often, and never when the app is idle in the tray. Record `t_response_headers − t_request_sent` so the bench shows the connect cost disappearing.

**5.7 Prompt prefix stability & provider caching.** Audit `PromptBuilder` / `SECTION_ORDER` so the prompt is **stable-prefix first, volatile last**: [identity + safety] → [mode instructions + schema] → [documents/personal instructions, deterministically ordered] → [session memory] → [transcript] → [screen] → [task line]. No timestamps, ids or per-request text in the prefix. This lets Gemini implicit caching (prefix ≥ ~1 K tokens on Flash — **VERIFY** the 3.x threshold), OpenAI automatic prompt caching (≥ 1024 tokens) and Anthropic `cache_control` (add breakpoints after system and after documents in the Anthropic codec) cut prefill time and cost. Optional (PR 5): Gemini explicit `cachedContents` for mode + documents with a 10-minute TTL refreshed while the HUD is active.

**5.8 Start earlier — speculative prefetch (PR 5).** When the HUD is shown or listening starts *and* screen permission is granted *and* the existing smart-observation setting is on, keep a **warm frame** (≤ 1.5 s old) via the observer's dHash: ⌘↵ reuses it when the hash is unchanged, otherwise captures fresh. Precompute retrieval for the current transcript question (5.5). Nothing new is captured silently — this only reorders work the user already opted into; say so in `docs/SECURITY.md`.

**5.9 Fast role tuning.** For `LatencyBudget::UltraFast | Fast`: `gemini-3.5-flash-lite` with `thinkingLevel: minimal`, `maxOutputTokens ≤ 400`, context budget ≤ 2,500 tokens + one image at `MEDIUM`; the default ⌘↵ trigger uses `Fast`; modes may raise to `Balanced` (their `latency preference` already exists); a **Think deeper** action re-asks on the reasoning role with the full budget. Structured output experiment: measure TTFT with `responseJsonSchema` vs plain markdown (the tolerant parser already handles fenced sections) over the seven mode fixtures × 5 runs; if schema costs > 150 ms p50, use markdown on the fast path and keep schema for `Balanced`/`Deep`.

**5.10 Hot-path hygiene.** Stop mirroring every `ai.chunk` onto the broadcast bus (keep it dev-only behind `dev-tools`; the WebView consumes the `Channel`); keep `ai.completed`. Consider a separate broadcast channel for high-rate `audio.level` so a lagging forwarder can't drop `app.state`. Neither changes the contract names.

## 8. Non-goals and forbidden

- **Single user, own accounts, own Mac.** No hosted proxy, no relaying, no sharing tokens with anyone else, no telemetry of prompts or screens. Several Google accounts belonging to the owner are fine; anything multi-tenant is out of scope.
- **Never spend the owner's money silently.** A request that a provider says is billed to extra usage / pay-as-you-go instead of the plan is a *stop* signal (§4b.5), not a retry.
- **Never retry a drifted fingerprint automatically.** Drift → `Unavailable`, fallback, notify; a human re-captures and bumps `VERSION`.
- **Do not weaken the secret boundary** to make OAuth convenient: tokens are Rust-only; the WebView sees `ProviderAccount` (status, plan, email, project) and nothing else; `secrets_set/delete` accept provider API keys only.
- **Do not route subscription tokens into the research sidecar** or any other child process.
- **Import from other clients is read-only**: never write to `~/.claude`, `~/.codex`, Antigravity's data directory, or their Keychain items.
- **No unpinned dependencies** (`latest`), no new root runtime dependency for sidecar-only needs, no edits to `.github/workflows/` outside `scripts/install-workflows.sh`.
- **No silent capture.** The warm-frame prefetch may only run when screen permission is granted and the existing smart-observation setting is on.
- **Fingerprints are data, not scattered constants**: one module per provider, `VERSION` + `CAPTURED_ON`, golden fixture, diff script. Any PR that touches a header or system block for one of these providers must update the fixture and the date.
