## Manual QA checklist
**Events reach the WebView** — the terminal log of `bun run tauri:dev` shows no `failed to emit event` line (a wire name Tauri rejects breaks every push to the UI); the HUD state pill follows `app.state` and the Settings window reflects changes made elsewhere without a reload.
**Authentication** — *Sign in with your browser* opens the default browser on Clerk; after signing in the browser lands on the `bluey://auth/callback` deep link (installed build) or the loopback page (`tauri dev`) and Bluey flips to signed in with the window brought to front · *Cancel* while waiting · deny/close the browser → toast, still signed out · relaunch restores the session (log: no `stored sign-in rejected`) · Sign out → signed-out card; Manage account opens the Account Portal · missing `VITE_CLERK_PUBLISHABLE_KEY`/`BLUEY_CLERK_OAUTH_CLIENT_ID` → configuration screen · the Clerk settings only in `.env.local` (no `.env`) → the boot log shows `loaded env file …/.env.local` and the sign-in card appears, not the configuration screen — in `tauri dev` and in a packaged build made while the file was present · an unrelated `bluey://…` link is ignored · Settings → AI still saves, shows and clears provider / Exa / Firecrawl / agent keys, and the Keychain entry `auth:clerk:oauth_tokens` written before the OAuth-engine extraction still restores the session on relaunch.
**Fingerprints (official CLIs installed)** — `bun run fingerprints:capture claude`, then `ANTHROPIC_BASE_URL=http://127.0.0.1:1456 claude -p "hi"` in another terminal: the proxy prints one line per exchange, the CLI's answer is unchanged, the capture under `tests/fixtures/fingerprints/claude/captures/` contains no token, e-mail or prompt text, and `bun run fingerprints:diff claude` reports only *VERSION* findings for a newer CLI (or the *DRIFT* the runbook then handles) · Codex via `chatgpt_base_url` · Antigravity via a MITM HAR + `fingerprints:import-har`.
**ChatGPT account (owner's subscription)** — Settings → AI → Accounts → *Connect ChatGPT*: consent once, the browser opens `auth.openai.com`, the loopback page says signed in, the card shows the plan badge (Free / Plus / Pro) and e-mail, the catalog lists only the plan's models and the unassigned roles pick them up · occupy port 1455 with another listener (`nc -l 1455`) and 1457 → the card shows a device code and `auth.openai.com/codex/device` · ⌘↵ streams from a Codex model with a screenshot; the log shows `accept: text/event-stream` and no `OpenAI-Beta` · hit the plan limit → the HUD says *Plan limit reached* with the reset time and the role falls back to Gemini until then; a later success flips the card back to connected · *Use recommended models* re-points the roles; *Disconnect* removes the Keychain entry (`security find-generic-password -s Bluey`) and the role assignments · relaunch restores the account without a browser · revoke the session at chatgpt.com → the next request shows *Reconnect* and the card *needs_reauth* · *Import Codex CLI sign-in* with `codex login` done: connected without a browser; the CLI keeps working until one side refreshes · Developer mode → *Probe fingerprint* reports *billed to your plan*.
**Claude account (owner's Max)** — Settings → AI → Accounts → *Connect Claude*: consent once, the browser opens `claude.ai`, the loopback page says signed in, the card shows *Claude Max 5×* and the e-mail · occupy port 54545 (`nc -l 54545`) → the flow uses another port; *Use device code* → the card asks for the pasted `code#state` from `platform.claude.com` · the catalog lists the plan's models (or the curated list — the card's *Refresh models* log line says which) · ⌘↵ streams from Sonnet with a screenshot; the log shows `POST /v1/messages?beta=true`, no `x-api-key`, and `bun run fingerprints:capture claude` + `ANTHROPIC_BASE_URL=http://127.0.0.1:1456 claude -p "hi"` gives the first real capture to diff · the **extra-usage guard**: if Anthropic answers *Third-party apps now draw from your extra usage…* the card shows *Paused to avoid extra-usage charges*, the role falls back to Gemini and no request is retried · a plan window 429 shows *Claude 5h limit — resets at …* and comes back on the next success · *Disconnect* removes the Keychain entry and the roles · *Import Claude Code sign-in* with `claude` signed in: connected without a browser (the Keychain may ask for permission); Claude Code keeps working until one side refreshes · Developer mode → *Probe fingerprint* reports *billed to your plan*.
**Google AI account (owner's Pro/Ultra)** — build with `BLUEY_ANTIGRAVITY_CLIENT_SECRET` set · Settings → AI → Accounts → *Connect Google AI*: consent once (it quotes Google's terms), the browser opens `accounts.google.com`, the loopback page says signed in, the card shows *Google AI Pro* (or Ultra) and the e-mail · occupy port 51121 (`nc -l 51121`) → the flow uses another port · the catalog lists the pool (or the curated list — the *Refresh models* log line says which) · ⌘↵ streams from `gemini-3.8-flash-high` with a screenshot; the log shows `POST /v1internal:streamGenerateContent?alt=sse` on one HTTP/1.1 connection with only `Content-Type`, `Authorization`, `User-Agent` · capture the real app once (`HTTPS_PROXY` + the capture proxy, `bun run fingerprints:capture antigravity`) and `bun run fingerprints:diff antigravity` — UA family, host, tier ids and the identity text are the open items · a `QUOTA_EXHAUSTED` 429 shows *Plan limit reached — resets at …* and comes back on the next success; a Terms-of-Service 403 shows *Account blocked by the provider* with the appeal address and nothing retries · *Disconnect* revokes the token and removes the roles · *Import Antigravity sign-in* with the standalone app signed in: connected without a browser (the Keychain may ask) · Developer mode → *Probe fingerprint* reports *Cloud Code answered on the Antigravity pool*; if it says the identity text was needed, re-capture.
**Fast path trace (Developer Mode)** — Settings → Advanced → *Fast path*: after one ⌘↵ the table shows capture · snapshot ready · retrieval · prompt built · request sent (local total) · response headers · first token · first paint · done as ms since the keydown, p50 / p95 over the last 50 requests; a typed question counts from the submit, a shortcut from the keydown (`shortcut.triggered.monoMs`) · the Developer overlay's `dev.log` shows `ai.trace` per request · `sqlite3 bluey.db 'select id, ttft_ms, trace from ai_requests order by created_at desc limit 3'` shows the merged JSON with `tFirstPaint` and `tDone` filled a moment after the answer (the late report) · *Run bench (mock, 10 runs)* prints the percentile table in the tab · `bun run bench:fastpath --iterations 30 --provider mock` from a terminal launches the app, prints the table, writes `.bench/fastpath-*.json` and exits 0; `--fixture tests/fixtures/screens/general-1440.jpg.b64` works without screen permission; `--provider gemini` (key configured) fills response headers / first token with real network numbers — paste both tables into `docs/LATENCY.md › Baseline`.

## Gemini smoke tests (real key, macOS)

With only `GEMINI_API_KEY` in `.env` (no other provider):

1. **Import** — first launch logs `imported api key for provider gemini` and nothing else; Settings → AI shows *Google Gemini* as the default provider with every role on its recommended model; the Keychain has `provider:gemini:api_key`; `.env` can be emptied afterwards.
2. **Chat** — ⌘↵ on a screen with text: first answer streams from `gemini-3.8-flash`; the dev overlay shows TTFT / tokens; no `temperature`/`topP` in the request (Gemini 3.x rules).
3. **Vision** — a screenshot with little text (a chart) yields an answer that references the image.
4. **Reasoning** — a system-design question in *System Design* mode uses `thinkingLevel: high` (longer TTFT, deeper answer).
5. **Structured output** — coding mode returns sections + a code block (JSON schema path).
6. **Embeddings** — add a résumé in Settings → Context; the document shows *Indexed · Embedded*; a question about it retrieves the right excerpt. Change *Embedding size* to 1536 → the document re-embeds (log: `re-embedding documents…`) and retrieval still works.
7. **Live transcription** — start listening with mic + system audio: partials then finals appear in the transcript strip with speaker labels; leave it running past 9 min 30 s → the log shows the rotation and no final is duplicated or lost; remove the key → the next start shows the *stt_fallback* toast and Apple Speech takes over.
8. **Batch transcription** — Settings → Sessions → *Import recording…* with a WAV/MP3: a new completed session “Imported · <file>” opens with a *Recording imported* timeline event and a Transcript section labelled *Speaker 1 / Speaker 2*; *Add recording* on an existing session appends to it; an `.m4a` is refused with a clear message; a file above 14 MB goes through the Files API (log: `transcribing recording … inline=false`) and the upload is deleted right after.
9. **Deep research** — a question that needs fresh facts with Exa/Firecrawl keys present: the pill shows *Researching*, the placeholder lists lookups, *Skip research* cancels the sidecar job, the answer carries citations; `RESEARCH_BACKEND=gemini` is the lite sidecar with `GEMINI_API_KEY` only in its environment.
10. **Errors** — a wrong key → *API key rejected* with the AI Studio link; a bogus model id → *Model not available*; exhaust the free tier → *Daily quota reached* / *Rate limited* with the retry delay.
11. **Switch providers** — Settings → AI → *Default AI provider* → Foundry: every role moves to the Foundry presets, the Foundry key field appears; switch back to Gemini with one click. `BLUEY_AI_PROVIDER=anthropic` in `.env` does the same at boot.
